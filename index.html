Set up an on-premises provider

YugabyteDB Anywhere (YBA) supports two kinds of on-premises provider. They differ in one thing: whether YBA gets root-level access to your database nodes. Answer the question below and follow the guide for your answer.

Will you give YBA an SSH user with passwordless sudo on your database nodes?

Yes

Privileged

  • YBA provisions each node over SSH, including kernel and OS settings.
  • You create the VMs and the SSH user, then add the bare VMs in YBA.
  • Manually Provision Nodes is OFF.
Set up a Privileged provider

No

Unprivileged

  • YBA never gets sudo. Your administrator runs node-agent-provision.sh on each node.
  • The script also creates the provider and adds the node to it.
  • Manually Provision Nodes is ON.

Still not sure?

These situations usually decide it.

If this is true for youChoose
Security policy does not allow third-party software to hold root or sudo accessUnprivileged
An OS team and a DB team share the work, and the DB team has no sudoUnprivileged
Node changes must go through your own automation or change controlUnprivileged
You want the fewest manual steps on each nodePrivileged
YBA may already reach the nodes over SSH as a sudo userPrivileged

Either way, YBA manages the universe through node agent after provisioning: creating universes, upgrades, scaling and backups work the same.

Already have a provider?

Open it in YBA and look at Manually Provision Nodes under Advanced.

  • OFF: Privileged guide
  • ON: Unprivileged guide

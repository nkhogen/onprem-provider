On-premises provisioning: Privileged or Unprivileged

With on-premises providers, YugabyteDB Anywhere (YBA) does not create VMs. You create the VMs and install a supported Linux OS, then add them to the provider’s free pool of nodes. Whether a node must be provisioned before you add it depends on the provisioning mode.

Will you give YBA an SSH user with passwordless sudo on your database nodes?

Manually Provision Nodes is OFF

Privileged. Yes, YBA gets sudo. You add bare VMs and YBA provisions them over SSH, including OS-level settings.

Unprivileged. No, YBA never gets sudo. Your system administrator runs node-agent-provision.sh on each node first; the script also adds the node to the free pool.

This switch works like the Manually Provision Nodes option under Advanced in the YBA provider settings. OFF is Privileged, ON is Unprivileged.

If you are unsure, start from your organization’s security policy. If granting root-equivalent access to YBA is not allowed, use Unprivileged provisioning.

Set up Privileged provisioning

YBA connects to each node over SSH as a user with passwordless sudo and performs all OS-level provisioning itself. After the VMs exist, you typically do not need to run anything on the nodes.

  1. Open the network. Have your network administrator open the ports YBA and the nodes need to communicate. See Networking.
  2. Create the VMs. Place them in the regions and availability zones where you will deploy universes, install a YugabyteDB-supported Linux OS, and create an SSH user with passwordless sudo on every VM (for example, ec2-user on AWS EC2). See Privileged provisioning requirements.
  3. Create the provider in YBA. Define regions and availability zones, provide the SSH credentials for the sudo-capable user, provide the NTP setup, and leave Manually Provision Nodes OFF. See Create the provider configuration.
  4. Define instance types. An instance type describes basic properties of the VMs you will add.
  5. Add the VMs to the provider. YBA provisions each VM automatically using the sudo-capable SSH user.
  6. Run pre-checks to validate the nodes. See Add nodes to the on-premises provider.
Turning on Manually Provision Nodes changes the mode. The provider becomes Unprivileged: YBA stops provisioning nodes, and each node must be prepared with node-agent-provision.sh before you add it.

Set up Unprivileged provisioning

YBA has no sudo access to your nodes. Your system administrator prepares each node by running the provisioning script, which also registers the node with YBA. Make sure YBA is installed and running first.

  1. Open the network. Have your network administrator open the ports YBA and the nodes need to communicate. See Networking.
  2. Create the VMs. Place them in the regions and availability zones where you will deploy universes, and install a YugabyteDB-supported Linux OS. See Software requirements for on-premises nodes.
  3. Provision each VM. Download the YBA node agent package to the VM, edit its configuration file, and run node-agent-provision.sh as root or via sudo. With YBA running, the script also creates or updates the provider (with Manually Provision Nodes ON), creates the instance type, and adds the node to the free pool. See Automatically provision on-premises nodes.

If the script didn’t create the provider or add the nodes

Create the provider in the YBA UI and turn Manually Provision Nodes ON under Advanced; see Manage the provider configuration. Then add the provisioned VMs using their IP addresses; see Add nodes to the on-premises provider.

Common questions

Which mode is “automatic”?

Both modes end with nodes that YBA manages automatically. The only difference is who performs OS-level provisioning: YBA (Privileged) or your administrator via the script (Unprivileged).

Does Unprivileged mean YBA can’t manage my universe?

No. After provisioning, YBA manages the universe through the node agent in both modes: creating universes, upgrades, scaling, backups, and so on.

What if I need to reprovision a node or apply OS changes later?

In Privileged mode, YBA performs them over SSH. In Unprivileged mode, your administrator re-runs node-agent-provision.sh on the node. See Reprovision nodes.
